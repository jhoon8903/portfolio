해달스도쿠 광고 흐름과 D0 → D1 개발 기록

상태를 구분해 읽기
- 10/1 첫 업데이트는 개발자의 배포 이력 설명에 따른다. 광고 흐름 코드 변경은 9/30 커밋에서 확인했으며 실제 릴리스 ID와 연결해 독립 확인한 것은 아니다. 이후 10/1–5 콘솔 일별 광고 시청률은 91.91–97.71%로 관측됐다.
- eCPM은 같은 기간 약 391–3,240원으로 흔들려 계속 모니터링한다. 지속 상승이나 광고 수익 증가를 주장하지 않는다.
- 뒤이은 포인트 튜토리얼·D1 데일리 퀘스트는 구현 및 Unity Editor 검증 단계다. 실제 포인트 지급과 D1 효과는 측정 전이다.

광고 관찰의 범위
- 9/23–29 콘솔 일별 광고 시청률: 26.50–48.04%. 9/30: 69.57% 전환 구간. 10/1–5: 91.91–97.71%.
- 콘솔 시청률은 요청·노출 수로 재계산한 값이 아니다. 일별 퍼센트의 평균을 내지 않았다.
- 9/23–30 광고 그룹은 4개, 10/1·2·4·5는 2개, 10/3은 3개다. 형식 구성과 트래픽이 통제되지 않아 단일 변경의 인과 효과로 해석하지 않는다.
- ad-performance.csv는 사용자가 제공한 콘솔 화면의 9/23–10/5 13개 행 전사본이다. ad-performance-2026-10-06.png는 같은 콘솔 원본 캡처다. 캡처의 노출 차트는 시청률 차트가 아니다.

시간순 변경
- 2026-09-30 코드 변경: Toss/WebGL의 생성 시점 전면광고 preload만 제거했다. 네이티브는 기존 preload를 유지한다. 전면광고는 사용자 show 시점에 로드하고, 로딩 중 입력을 막는다. 기존 첫 전면광고 레벨 15 규칙은 변경하지 않았다.
- 2026-10-01: 위 첫 업데이트가 배포됐다는 개발 기록. 기회·로드·표시·닫힘 이벤트를 추가하고, 전면광고 10초·리워드 8초 로드 대기, 저장된 마지막 표시 시각, 120초 쿨다운을 적용했다.
- 2026-10-01: 6개 필수 지시를 해달 놓기 → X 표시 → 마지막 해달 찾기의 3행동으로 축소했다. 시작 해달 3개, 보드 5×5 → 6×6 → 7×7, 1→2→3 직행을 적용했다.
- 2026-10-03–05: 7일·270 진주 목표는 로컬 옵션으로 철회했다. 초기 D1 안은 3판 진행 표시(남은 2/1), 3판 클리어, 명시적 1원 받기, 실제 성공, 다음 KST 방문 혜택으로 구성했다. 10/5에는 초기 직접 배치 뒤 지급안을 3판 완료 뒤로 변경했다.
- 2026-10-06 현재 코드: 첫 지급 뒤 반복 퀘스트는 스테이지 클리어 3회, 해달 15마리, 진주 6개를 모두 완료해야 Ready가 된다. 새 스테이지 진행만 세고 KST 날짜마다 진행을 초기화한다. 실제 설정과 코드의 maxRewardedDays는 0(캠페인 로컬 상한 없음)이다. 초기안의 2회 상한을 현재안으로 표기하지 않는다. 지급은 운영 기간과 플랫폼의 일일 한도 안에서 처리한다.

D1 지급 경계와 검증
- 첫 혜택은 1포인트다. KST 날짜를 사용하며, 현재 반복 퀘스트의 진행은 날짜마다 초기화한다.
- Pending 예약을 저장한 뒤 요청한다. Rejected/NotSent은 저장 성공 뒤 재시도할 수 있고 Unknown/Pending은 재로드·자정에도 자동 재요청하지 않는다.
- 2026-10-05: 15개 도메인 경로, 23개 타일 색 검사, 3판 후 Ready 재시작 보존, 컴파일 오류 0개를 확인했다. 실제 지급 호출·실기기 입력·라이브 D1은 검증하지 않았다.
