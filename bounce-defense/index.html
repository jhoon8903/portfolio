무엇을 고쳤나

해결할 문제
반사·관통 이동 처리와 카드 선택에 따른 스킬 조합 규칙을 일관되게 구현해야 했습니다.
직접 구현한 범위
  • CircleCast로 남은 이동 거리까지 충돌을 처리했습니다.
  • 반사·관통 분기와 스킬 효과·피해 보정을 분리했습니다.
  • 카드 선택과 로드아웃 규칙을 테스트로 검증했습니다.
확인한 결과
  • 카드·로드아웃·레벨 관련 테스트 26개를 남겼습니다.
  • 액티브 4개와 패시브 2개 보유 한도를 구현했습니다.

구현 과정

  1. 01

    남은 이동 거리까지 충돌

    CircleCast로 이동 경로의 충돌 지점을 찾고 남은 거리까지 처리했습니다. 한 프레임 이동 안에서도 반사와 관통 분기가 이어지도록 구성했습니다.

  2. 02

    스킬 조합을 모듈화

    충돌의 법선 반사·관통 횟수 처리와 스킬 효과·피해 보정을 분리했습니다. 카드 선택이 바뀌어도 전투 규칙의 책임이 섞이지 않게 했습니다.

  3. 03

    보유 규칙을 테스트

    카드·로드아웃·레벨 관련 26개 테스트로 선택 규칙을 검증했습니다. 액티브 4개와 패시브 2개 보유 한도도 같은 규칙으로 다뤘습니다.

개발 노트

충돌 후 남은 이동 거리를 반복 처리합니다.보기닫기

한 프레임의 이동 중 여러 표면에 닿거나, 관통 중 같은 적을 반복 타격하는 상황을 처리해야 했습니다. KinematicRaycastMotor에서 공 반경을 포함한 CircleCast 결과 중 가장 가까운 접촉을 선택하고, 충돌 이후 남은 거리를 다시 계산했습니다.

연속 충돌 처리

속도 × 시간으로 이동 거리를 구하고, 접촉점까지의 이동 거리를 빼고 다음 충돌을 계산합니다.

반사

접촉 법선으로 방향을 반사하고 속력을 유지합니다. 접촉면에서 0.01만큼 떨어뜨려 즉시 재접촉하는 상황을 줄였습니다.

히트 중복 방지

현재 스텝의 피격 목록과 비행 중 통과한 콜라이더를 관리해, 관통 중 겹쳐 있는 적을 프레임마다 재타격하는 문제를 막았습니다.

반사 분기의 실제 코드 일부

float travel = Mathf.Clamp(wallDist, 0f, remaining);
_position += dir * travel;
remaining -= travel;
_velocity = Vector2.Reflect(_velocity, wallNormal).normalized * _speed;
_position += wallNormal * SkinWidth;

코드 확인: KinematicRaycastMotor.cs · MotorGeometry.cs · TrajectoryPreview.cs

궤적 예측의 범위와 반복 제한

실제 이동과 미리보기는 벽 경계 계산을 공유하는 별도 시뮬레이션입니다. 미리보기는 장애물을 반사하며 관통 볼의 경로까지 완전히 일치시키지는 않았습니다. 실제 모터는 스텝당 최대 8회 반복하고 16개 캐스트 결과 버퍼를 사용합니다.

스킬 수치와 동작을 분리해 조합합니다.보기닫기

스킬마다 이동 로직과 데미지 계산을 복제하면 조합이 늘수록 수정 범위가 커집니다. 레벨별 수치는 SkillDefinition 데이터에 두고, 효과는 볼 모듈과 데미지 보정으로 분리했습니다. SkillRuntime은 로드아웃 변경을 구독해 볼 구성과 효과를 갱신합니다.

새 프로젝트의 렌더링 상태를 최적화 전 기준으로 남깁니다.보기닫기

아래 자료는 후속 프로젝트 Bounce Fit의 Unity Editor 화면입니다. 카드 선택과 전투를 구현한 현재 상태를 기록하고, 일반 Draw와 SRP Batcher 경로가 교차하는 구간을 최적화 검토 대상으로 잡았습니다.

기존 Bounce-Defense의 7월 측정 기록과 다른 프로젝트의 자료입니다. 현재는 최적화 전 상태만 확보했으며, 두 자료를 전후 개선 수치로 연결하지 않습니다.

관찰한 현상

투명 패스 안에서 일반 Draw와 SRP Batcher 경로가 반복 교차합니다. 전체 이벤트 수와 해당 패스의 구성을 기준 자료로 보존했습니다.

확인할 원인

인접한 Draw의 렌더러·머티리얼·셰이더와 SRP 이벤트의 Batch cause를 확인해, 배칭 가능한 대상의 분리인지 필수적인 경로 혼재인지 구분합니다.

개선 판단 기준

동일한 전투·정렬·이펙트·해상도 조건으로 다시 캡처하고, Profiler의 렌더링 CPU 시간도 비교해 효과를 판단합니다.
