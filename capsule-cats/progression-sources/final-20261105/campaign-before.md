# 고정 유닛·강화표로 Stage1→10 연속 성장 검증

> **후속 사용자 정정 (2026-11-03):** 매 스테이지에서 같은 스테이지 반복 → 참치 획득 → 추가 강화 → 돌파가 필요하다. 아래 실행 원본·통계는 보존하지만, Stage3–10 첫판 통과를 근거로 한 수치 유지·밸런스 완료 판단은 철회한다. 최신 기준은 [성장 루프 검증 계약](../../STAGE_GROWTH_CONTRACT.md)이다. 새 후보 적용·검증은 미완료다.


**결론: Stage1 B·Stage2 F와 공통 유닛·강화 수치를 유지한다.** 신규 50여정 모두 실제 획득 보상으로 성장하며 Stage10을 클리어했다. Stage2의 3회 이후 정체는 추가 성장으로 회복됐다. 이번 검증에서는 게임 수치를 변경하지 않았다. 이는 자동 전투 정책에서의 진행 가능성 확인이며 출시 밸런스나 재미의 확정을 뜻하지 않는다.

## 문제와 실험의 교정

이전 Stage2 실험은 3회 안에 통과했는지를 비교했다. 실제 진입자 97명 중 획득 강화 조건 45명이 통과했고, 실패 52건 중 48건은 W10, 4건은 W9에서 끝났다. 이는 후반 압박의 위치를 보여주지만 성장으로 결국 극복할 수 없는지를 증명하지 않는다. 사용자는 실제 획득 강화로 극복 가능하면 낮은 3회 성공률만으로 수정하지 말라고 정정했다.

선택 실패자의 연장 실험은 8건 완료 시점에 중단했다. 모두 4~5회차에 회복했지만 앞부분 45전투를 반복하는 비용이 발생했다. 이를 전체 모집단 성공률로 합산하지 않았다. [무결성·효율 감사](../../audits/2026-11-03-efficiency-integrity/REPORT.md) 후, **같은 기본 능력치와 강화표를 유지한 연속 여정**을 주 실험으로 바꿨다. 실제 입력 해시 범위도 경제·씬·프리팹·Framework·설정·meta를 포함하도록 보완했다.

## 고정 조건과 표본

- 사전 고정 신규 시드 990001–990050, 독립 여정 50개, 실제 ECS 전투 714회. pilot 4개와 과거 표본은 합산하지 않았다.
- [고정 기준표](../../baselines/2026-11-03-unit-progression-v2/README.md): 8직업×5등급 기본값 40행, 강화 0–5레벨 능력치 240행, 비용 25행.
- 모든 스테이지에서 공격 배율 `1+2×레벨`, HP 배율 `1+레벨`, 최대 레벨 5. 등급별 기본값·강화 비용도 동일한 표를 사용한다.
- 여정 내 참치·강화 상태를 승계하며 balanced 정책으로 구매한다. 추첨과 실제 구매 대상은 시드마다 달라질 수 있다. 영구 강화 합계는 DPS가 아니다.
- 별도 파밍·외부 재화·광고·결제 공급 없음. 재시도 횟수 제한 없음. 누적 전투 3,600초가 관측 한도다.
- 여정마다 새 Play와 격리 저장 상태로 시작하고, 단일 Editor에서 직렬 실행했다. [사전 계획](PROTOCOL.md), [실행 manifest](manifest.json).

3회 안에 통과하지 못한 **28여정 모두 이후 회복**했다. 이 28명은 이전 실험의 실패 52명과 다른 신규 표본이다. Stage1은 첫판 1명, 2회차 18명, 3회차 31명이 통과했다. Stage3–10은 각 단계 진입자 50명 모두 첫 도전에 통과했다. **각 스테이지 클리어 보상으로 이후 강화 구매도 계속됐으므로 Stage2의 성장만으로 나머지를 통과했다고 해석하지 않는다.**

선은 개별 여정과 중앙값, 음영은 10–90백분위이며 신뢰구간이 아니다. 첫 진입 강화 합계의 평균은 Stage2 15.36, Stage3 48.60, Stage10 65.94다. 직업·등급별 실제 시작 레벨은 원본 `beginningLevels`, 구매 내역은 `tables/upgrades.csv`에 있다.

## 결정과 다음 제품 판단

이번 결과는 Stage2 F의 HP·보상을 추가 조정해야 한다는 근거를 제공하지 않는다. 임의 70%나 3회 제한에 맞추는 후보 탐색을 하지 않고 **현재 수치를 유지**한다. 고정 기준을 먼저 만들고 지속 성장과 적·웨이브 압박의 관계를 관측한다는 사용자 지시를 따른 결정이다.

관측된 재도전은 Stage1–2에 집중되고 Stage3–10은 성장 후 연속 통과한다. 이 흐름을 첫 캠페인의 의도로 유지할지, 후반에 추가 도전 구간을 둘지는 사용자 플레이와 제품 의도의 판단 대상이다. 후자를 선택하면 유닛 기본값을 다시 흔들지 않고 후반 적 HP·공격력·구성·웨이브를 별도 후보로 비교해야 한다. 이번 결과만으로 강제 패배 구간을 추가하지 않는다.

D0~D몇 도달, 참치 BM 지급량·가격, 실제 구매 단축 효과, 사람의 재미·이탈, 기기 성능·전체 UI 동등성은 측정하지 않았다. 서버의 Stage2 보상 상한 36 반영은 로컬 소스 상태이며 배포 완료를 주장하지 않는다.

## 검증과 원본 추적

[검증 기록](validation.json): 50개 job 완료, 50회 복원 PASS, 1,361개 입력 파일의 전후 해시 동일, 현재 파일도 일치. 고정표 원본 9개 해시도 일치한다. 이번 50여정에는 복구 재시작이 필요하지 않았다. 최종 Editor는 ready/stopped이며 복구 marker가 없다. [상태 기록](analysis/editor-final-status.txt).

[CSV 6종](tables/)은 여정 50행, 전투 714행, 웨이브 10,955행, 경제 4,093행, 강화 3,379행, 스테이지 요약 10행이다. [원본](results/)과 [마감 시점 원본 SHA256 목록](analysis/raw-sha256.json)을 보존했다. 이 해시 목록은 마감 시점의 스냅샷이며 과거의 독립 타임스탬프 증명은 아니다. 표준 `stage_clear_within_3.svg`는 제한 회차 진단용이므로 전체 캠페인 결론에는 위 연속 성장 차트를 사용한다.

분석기는 시드·입력·순차 진행·참치 원장·강화 승계·시간 검열을 검사한다. [완료 감사](COMPLETION_AUDIT.md)와 [통계](analysis/final_statistics.json)를 함께 읽는다. 자동 ECS 증거는 사람 플레이나 배포 검증을 대체하지 않는다.

## 에이전트 기여와 재현

- 메인: 사용자 요구 정리, 단일 Editor 실행, 고정표 추출, 입력 해시 확대, 원본/복원 확인, 최종 집계·차트·판정.
- `continuous_campaign_analysis` worker: 연속 캠페인 원장·성장·검열 분석기와 회귀 검사. 메인이 통합하고 분석 결과를 검토했다.
- `simulation_integrity_review` reviewer: 과거 Stage2 원본 재집계와 표본·해시 범위·효율 문제 독립 감사. 최종 50개 결과를 별도 검토했다고 주장하지 않는다.

반복 전투는 배치 코드가 수행했다. 에이전트별 토큰 절감률은 측정하지 않았다. 신규 전투 없이 결과를 재집계하려면 프로젝트 루트에서 실행한다.

```bash
python3 docs/Simulation/runs/2026-11-03-continuous-campaign-validation/analysis/analyze_campaign.py --run docs/Simulation/runs/2026-11-03-continuous-campaign-validation --manifests manifest.json --output docs/Simulation/runs/2026-11-03-continuous-campaign-validation/analysis
python3 AgentScripts/export_simulation_results.py --input docs/Simulation/runs/2026-11-03-continuous-campaign-validation/results --output docs/Simulation/runs/2026-11-03-continuous-campaign-validation
python3 docs/Simulation/runs/2026-11-03-continuous-campaign-validation/analysis/finalize_results.py
uv run --with matplotlib python docs/Simulation/runs/2026-11-03-continuous-campaign-validation/plot_results.py
```

`finalize_results.py`는 현재 파일과 실행 당시 입력이 달라지면 중단한다. 이후 새로운 후보를 만들 때는 과거 실험을 덮어쓰지 않고 새 버전으로 기록한다.
