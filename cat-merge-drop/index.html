무엇을 고쳤나

해결할 문제
준비 전략별 진행 여유를 같은 조건에서 비교하고, 장기 진행 병목의 원인을 분리해야 했습니다.
직접 구현한 범위
  • Unity 설정을 읽어 공통 입력 스냅샷을 만들었습니다.
  • 4개 예산·4개 정책·20개 시드로 320회 실행했습니다.
  • Unity ECS World 결과와 Python 계산을 표본 전투로 대조했습니다.
확인한 결과
  • 기본 Drop 예산을 4회에서 10회로 조정했습니다.
  • 세 머지 정책이 각 n=20 시드에서 1,000단계를 재시작 없이 완료한 조건을 확인했습니다.

구현 과정

  1. 01

    입력 스냅샷 공유

    Unity에서 스테이지·고양이·브릭·경제 설정을 읽어 입력 해시가 있는 공통 스냅샷을 만들었습니다. 모든 실행이 같은 스냅샷을 받아 비교 중 설정이 섞이지 않게 했습니다.

  2. 02

    조건 행렬 실행

    Drop 예산·자동 정책·시드를 실행 인자로 분리해 조합별 목록을 만들었습니다. 완료 단계, 중단 구간, 재시작 횟수를 실행별 원자료와 집계에 남겼습니다.

  3. 03

    ECS 결과와 교차 검증

    격리된 Unity ECS World 전투 결과를 Python 계산과 대조했습니다. 212개 편성·586개 Drop 표본에서 보상, 누적 HP, 생존 슬롯과 프레임 차이를 확인했습니다.

개발 노트

한 전략의 클리어 여부만으로는 장기 진행의 병목을 판단하기 어려웠습니다.보기닫기

이 게임은 고양이를 소환·머지한 뒤 낙하 전투로 브릭을 파괴합니다. 한 번의 전투를 Drop이라고 부릅니다. 준비 방식과 도전당 전투 횟수가 함께 진행에 영향을 주므로, 여러 전략을 같은 조건에서 비교할 필요가 있었습니다.

‘한 번 준비·집중’ 정책은 20개 시드 모두 12단계 완료 후 13단계에서 중단됐습니다. 소환·머지를 반복하는 정책은 18개 실행이 1,000단계를 완료했지만, 전체 20개 실행에서 1,847회의 무료 재시작이 발생했습니다.

확인할 질문은 “준비를 반복하지 않는 전략에도 진행 여유가 있는가?”였습니다. 소환 가격이나 맵을 동시에 바꾸면 원인을 구분하기 어려워, Drop 제한을 비교 변수로 정했습니다.

소환·머지·전투·보상·재시작을 자동 정책으로 실행하도록 만들었습니다. 조건 조합을 실행 목록으로 만들고, 같은 입력 스냅샷을 모든 실행에 전달해 비교 중 설정이 섞이지 않도록 했습니다.

적용한 변경

기본 Drop 예산 4 → 10회

비교한 네 조건 중 머지를 사용하는 세 정책이 모두 20/20으로 1,000단계를 재시작 없이 완료한 조건은 10회였습니다. 반복 준비는 6회에서도 완료했지만, 한 번 준비·집중은 6회에서 65단계, 8회에서 292단계에 막혔습니다. 단순한 준비 전략에도 진행 여유를 확보하는 쪽으로 결정했습니다.

잘 준비한 전략의 속도는 유지

10회 제한에서 반복 준비는 단계당 평균 3.50회, 분산은 4.38회, 단순 집중은 7.47회에 완료했습니다. 빨리 끝낼 수 있는 전략에 추가 Drop을 강제하지 않습니다.

남은 문제도 기록

머지를 미루는 마릿수 보존 정책은 10회에서도 4단계에서 중단됐습니다. Drop 확대만으로 모든 준비 방식을 구제하지는 못했으며, 머지 규칙의 이해와 실제 플레이 경험은 후속 검증 대상입니다.

9회는 측정하지 않아 10회를 최소값으로 주장하지 않습니다. 자동 정책은 인간 승률·재미의 측정값이 아니며, 일부 정책은 시드가 달라도 같은 결과가 나옵니다.

실행 조건의 분리

조건이 바뀌면 비교 실행을 다시 구성

비교할 전투 횟수, 플레이 정책, 시드, 진행 단계와 중단 한도를 실행 인자로 분리했습니다. 조건의 조합으로 실행 목록을 만들고 워커 수에 따라 순차 또는 병렬로 실행합니다.

# 비교 실행 코드에서 발췌
snapshot = load_current(root)
jobs = [
    (seed, policy, budget, args.stage_limit,
     args.max_restarts, args.max_actions)
    for policy in policies
    for budget in budgets
    for seed in seeds
]

새 비교에서도 동일한 실행·집계 경로를 사용합니다. 현재 도구가 직접 비교하는 수치는 전투 횟수이며, 다른 밸런스 변수로 확장하려면 해당 모델과 실험 조건도 수정해야 합니다.

판단 근거의 보존

결과와 입력값·중단 이유까지 기록

  1. 어떤 설정으로 실행했는가소스·에셋 해시, 경제 설정, 시드, 실행 한도 기록

  3. 어떤 조건을 채택할 것인가정책·수치별 완료 수, 평균·P95, 병목 구간 집계

실행별 원자료와 집계를 JSON에 함께 남겨 결론의 근거를 추적할 수 있게 했습니다. 포트폴리오에는 같은 기록을 비교 표와 CSV로 제공했습니다.

실행 조건과 집계 결과

변경 후 확인

실험에 사용한 값과 실제 적용값을 다시 대조

최종 게임 설정을 읽어 세 머지 정책을 시드 1로 재실행했고, 10회 비교군의 해당 실행과 전체 지표가 일치하는지 확인했습니다. 실제 게임의 표본 전투와 모델 대조도 다시 수행했습니다. 설정 변경을 실험 결과와 연결해 확인하는 절차입니다.

최종 설정으로 20개 시드 전체를 재실행한 것은 아닙니다. 시스템화한 범위는 자동 정책의 진행 검증이며, 인간의 재미·조작 경험과 실제 기기에서의 플레이 검증은 별도로 필요합니다. 작업 시간 절감률은 측정하지 않았습니다.
