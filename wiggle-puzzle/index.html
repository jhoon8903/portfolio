무엇을 고쳤나

해결할 문제
여러 캐릭터의 BFS 경로 계산이 한 프레임에 몰려 입력 반응과 프레임 안정성을 해쳤습니다.
직접 구현한 범위
  • Profiler로 경로 탐색 병목을 측정했습니다.
  • Jobs·Burst로 경로 계산을 병렬화했습니다.
  • Galaxy A·Poco·저전력 모드에서 다시 확인했습니다.
확인한 결과
  • Profiler 측정에서 600ms+ 지연을 50ms 이하로 낮췄습니다.
  • 저사양 기기에서 60fps 유지를 확인했습니다.

구현 과정

  1. 01

    계산 경계 분리

    보드 상태가 바뀔 때 반복되는 BFS를 Job으로 옮겼습니다. 메인 스레드의 입력 처리와 경로 계산이 한 프레임에 겹치지 않게 했습니다.

  2. 02

    수명·반납 규칙 고정

    NativeContainer의 수명과 Pool 반환 책임을 인터페이스 경계에 명시했습니다. 컨테이너와 객체를 재사용해 생성·해제 규칙을 대칭으로 유지했습니다.

  3. 03

    구조와 기기 재검증

    VContainer 스코프에서 Factory·Controller·EntryPoint의 역할을 분리했습니다. Profiler 수치와 Galaxy A·Poco·저전력 모드의 60fps 확인을 구분해 기록했습니다.

Architecture

의존성과 수명을 한 방향으로 정리했습니다.보기닫기

VContainer 스코프 안에서 Factory, Controller, EntryPoint의 역할을 분리하고, 생성과 해제가 대칭이 되도록 규칙을 고정했습니다.

  1. Factory — Pool 객체 생성·반환
  2. Controller — 상태·규칙·Command
  3. EntryPoint — 조립·시작·해제
입체적인 겹침을 유지하며 렌더 상태 변경을 관리했습니다.보기닫기

2D 스프라이트로 입체적인 앞뒤 관계를 표현하기 위해 Sorting Group과 그리기 순서를 분리했습니다. 이 정렬 제약을 유지하면서, 세그먼트·타일·슈터의 공유 머티리얼과 SRP Batcher 호환 구성을 적용했습니다.

2026.09.12 Game 씬의 활성 오브젝트 540개를 전수 조회했습니다. Renderer 사용 여부는 실제 화면 표시 개수와 구분합니다. 집계 기준 보기 ↗

입체감을 위한 정렬Sorting Group을 Y 위치에 따라 정렬하고 세그먼트의 그리기 순서를 제어합니다. 오브젝트가 겹칠 때도 필요한 앞뒤 관계를 유지합니다.

공유 머티리얼 · SRP색상별 머티리얼을 캐시하고 sharedMaterial로 재사용합니다. 해당 색상 처리에는 MaterialPropertyBlock을 사용하지 않아 SRP Batcher 호환성을 유지합니다.

렌더링 범위 관리Sprite Atlas를 적용하고, 화면 밖 세그먼트는 Renderer를 비활성화해 렌더링 대상에서 제외했습니다.

캡처 범위 SRP Batch 3개는 한 프레임에서 선택한 RenderLoop.DrawSRPBatcher 구간의 스프라이트·텍스트 배치 구성입니다. UI와 효과를 포함한 전체 Game 뷰의 SetPass Calls 19회와 구분해 표기했습니다.
